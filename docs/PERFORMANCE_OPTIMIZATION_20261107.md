# Node Manager 与 sing-box 本地性能优化

对应 2026-11-07 的 24 小时监控审查。本轮修改只在本地，未部署、重启生产、修改线上任务或提交 Git。保留工作区已有修改；`runtime_publication.py` 的 metadata-fence / WAL v2 与队列的其他既有改动一起组合验证，不作为本轮新实现重复归功。

## Node Manager

### 配对只读投影

`singbox.manager.get_user_monitoring_snapshot()` 返回不可变的策略、认证映射、执行状态、用户计数及 SOCKS 端口投影。文件版本包含路径、设备、inode、大小、mtime 和 ctime。缓存命中不等待整个配置发布锁；缓存缺失仍在共享锁下读取同一文件对，并核对读取前后的版本。

写入、回滚与恢复之前失效；未决 runtime/revision WAL 不允许使用全局缓存；事务 workspace/capture 也不借用已提交投影。保留目标预检、CAS、单写入器、持久化及不确定结果恢复。

心跳使用原注册表用户数口径，节点列表使用原受管协议列表计数口径，两者没有强行合并。版本查询按实际二进制文件身份缓存；文件替换、PATH/软链接变化使缓存失效，失败查询可重试。

### 采集与策略写入

采集提交策略变更时将调用方等待预算设为 0，取得已受理任务后交还采集流程；并未取消任务或改变写入顺序。后续采集跟踪同一任务；UNKNOWN 或无法核对的结果不盲目重投。调用方预算在 finally 恢复，普通 HTTP 写入仍保留原等待行为，显式 `timeout=None` 语义也保留。

非阻塞受理必须配合收敛判断：同步前使用同版本的已提交 enforcement 投影核对当前意图，已满足时不新增任务；真实变更仍由写入器在锁内重算。不能在未提交 mutator 内建立全局 no-op 缓存，也不能仅因旧意图成功就跳过当前相反意图。

累计计费、原生计数 epoch、撤销尾量、配额判定和持久化方式保持原有约束。本轮没有通过降低计费频率或关闭 fsync 提速。写文件到核心应用期间仍保守等待，不声称所有锁等待已经消除。

### 状态与诊断

连接观测、观测新鲜度和策略执行结果分开表达。较新的合法观测即使已经 stale 仍更新展示值，保留实际观测时间并明确不可用原因；较旧、未来、无时区或非法时间不覆盖合法值。

每个指标提供自己的采样时间、年龄及可用性。某一字段失败不再冻结其他字段的成功时间，另保留最后整轮成功时间。计费 API 的严格 available 语义没有因展示层改动而放宽。

账本增加 `connectionsCollectedAt`：仅原生累计量更新、Clash 连接查询失败时，保留旧连接时间，不把旧连接列表伪装成新样本。旧账本仍能读取。

心跳模型保留允许的观测/策略状态字段，并继续过滤连接与用户明细。非法时间在模型边界保守降级，避免响应 500。增加固定类别的采集、计数、连接、投影、策略及账本持久化阶段耗时；统计是进程累计数据，不是全天分位数，任务结果应以队列回执为准。

## sing-box

- 内存查询与连接快照共享最多 1 秒的安全内存采样；单独查询内存不再遍历所有连接。没有缓存整份连接明细，在线列表保持实时读取。
- 按 ID 关闭连接使用已有索引，保留 DNS 排除及未知 ID 返回 204 的接口行为。
- 累计计数在锁内复制，排序移到锁外。未删除历史计数或改变累计 epoch。
- Accept 临时错误采用 5 ms 起、最多 1 秒的退避，成功后清零；永久错误退出循环，取消上下文可中止等待。

本轮没有改认证协议、GC 参数、MTU、缓冲区或现有客户链接。
